本目录为《小哭包和宝宝的周末旅行日记》的**完整独立本地工程**。

## 一、软件工程设计原则解答：为什么必须“本地修改 ➜ 推送云端”？

> **您的直觉非常敏锐而且完全正确！现代软件开发 100% 都是这样设计的。**

在专业软件工程与互联网开发规范中，有两条铁律：
1. **“本地即沙盒，云端即生产”**：
   - 自己的电脑（本地环境）是安全的“实验工坊”。在这里无论怎么改代码、调试图片、甚至改错报错，都**只影响自己电脑，绝不会影响公网上的真实访客**。
   - 只有在本地测试确认完全满意、无任何 BUG 后，才统一推送到云服务器（生产环境）。
2. **严禁“直接在云端改代码”（No Live Hot-Patching）**：
   - 直接在云服务器上修改线上文件非常危险，一旦手抖打错一个符号，线上网站可能瞬间白屏崩溃（502 Bad Gateway）；同时本地与云端代码会脱节，时间一长就会不知道哪个版本是最新的。
3. **“代码与数据分离”**：
   - 网页代码（HTML/CSS/JS/图片）在本地开发维护，部署时覆盖到云端；
   - 用户发表的感言（`diary.db`）保存在云端，部署代码时**绝不覆盖数据库**，两全其美。

## 三、日常修改与上线工作流（推荐 3 步走）

### 第一步：在本地进行修改
用任意编辑器打开 [site/index.html](file:///f:/web_design/travel-diary/site/index.html) 或向 `site/assets/` 添加新图片。

### 第二步：在本地运行预览（免上网测试）
在终端中进入本项目目录并运行：
```bash
python preview.py
```
* 会自动在本地启动 `http://127.0.0.1:8080`；
* 自动在电脑浏览器打开页面，包含模拟随机封面与本地独立的测试留言数据库（**绝不污染云端**）；
* 预览满意后，按 `Ctrl + C` 退出。

### 第三步：一键推送到云端上线
确认本地效果完美后，在终端运行一行命令：
```bash
python deploy.py
```
* 脚本会自动连接云服务器 `36.151.149.94`；
* 自动增量上传修改后的网页和图片；
* 自动热重载 Nginx 与后端守护进程；
* 自动进行公网健康探测。显示 `恭喜！本地修改已全部成功同步上线！` 即可在手机上直接看到最新改动！

## 四、未来如何添加新活动（如 Vol.02 成都/海岛大冒险）？

1. **准备新插画**：
   把新活动的 3 篇竖版连环画保存为 `story-vol2-1.webp`、`story-vol2-2.webp`、`story-vol2-3.webp`，放进 `site/assets/` 目录。
2. **点亮目录卡片**：
   打开 `site/index.html`，找到注释 `<!-- 冒险 2：下一站筹备中 -->`，把它的 `class="adventure-card locked"` 改为 `class="adventure-card"`，并填入新标题与图片路径。
3. **执行一键推送**：
   运行 `python deploy.py`，几秒钟内云端即刻上线新冒险，且新冒险会自动拥有属于自己的独立感言留言板！
